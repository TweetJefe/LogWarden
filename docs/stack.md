# LogWarden — технологический стек

## Основной стек

| Область | Технология | Назначение |
|---|---|---|
| Язык | Python 3.14 | Основной язык проекта |
| API | FastAPI | Приём инцидентов, запуск расследований и выдача отчётов |
| ASGI-сервер | Uvicorn | Запуск FastAPI-приложения |
| Валидация данных | Pydantic v2 | Схемы запросов, доказательств, гипотез и отчётов |
| Настройки | pydantic-settings | Конфигурация через переменные окружения и `.env` |
| Описание агентов | Pydantic AI | Инструкции, инструменты, зависимости и типизированные результаты агентов |
| Оркестрация | LangGraph | Переходы между этапами расследования, ветвления и состояние графа |
| LLM-провайдер | OpenRouter | Доступ к выбранным языковым моделям |
| Модели LLM | Настраиваются для каждого агента | Выбор модели под анализ логов, кода и подготовку отчёта |
| Основная БД | PostgreSQL | Инциденты, расследования, доказательства и отчёты |
| Работа с БД | SQLAlchemy 2 | Модели данных, запросы и транзакции |
| Драйвер PostgreSQL | psycopg 3 | Подключение Python к PostgreSQL |
| Миграции | Alembic | Версионирование прикладной схемы БД |
| Состояние графа | langgraph-checkpoint-postgres | Контрольные точки и возобновление расследований |
| Фоновые задачи | Celery | Выполнение расследований в worker-процессах |
| Брокер задач | Redis | Передача заданий от API к worker |
| HTTP-клиент | HTTPX | Запросы к источникам логов, Git API и мониторингу |
| Логирование | `logging` + JSON-формат | Структурированные логи LogWarden |
| Управление зависимостями | uv | Виртуальное окружение, установка пакетов и запуск команд |
| Конфигурация проекта | `pyproject.toml` + `uv.lock` | Настройки проекта и воспроизводимая установка |
| Тестирование | pytest + pytest-asyncio + HTTPX | Тесты бизнес-логики, асинхронного кода и API |
| Линтинг и форматирование | Ruff | Проверка кода и единый стиль |
| Проверка типов | mypy | Статическая проверка аннотаций |
| Контейнеризация | Docker | Изолированные окружения приложения и worker |
| Локальная инфраструктура | Docker Compose | Совместный запуск API, worker, PostgreSQL и Redis |
| Контроль версий | Git | История кода и совместная разработка |
| IDE | PyCharm | Разработка и отладка |

## Ответственность компонентов

```text
Клиент
  |
  v
FastAPI
  |
  +--> PostgreSQL
  |
  +--> Redis --> Celery worker --> LangGraph
                                  |
                                  +--> Pydantic AI
                                         |
                                         +--> OpenRouter --> LLM
```

- **FastAPI** принимает инцидент и возвращает статус расследования.
- **Celery** запускает длительную работу в отдельном worker-процессе.
- **LangGraph** управляет маршрутом расследования и состоянием процесса.
- **Pydantic AI** описывает отдельных агентов, их инструменты и результаты.
- **OpenRouter** предоставляет доступ к LLM и позволяет выбирать модель для каждого агента.
- **PostgreSQL** хранит прикладные данные и отчёты.
- **Alembic** управляет миграциями прикладных таблиц.
- **Redis** используется как брокер задач Celery.

## Источники данных

| Данные | Первая версия | Дальнейшее развитие |
|---|---|---|
| Логи сервиса | JSON-файлы | Loki, Elasticsearch или другой источник логов |
| Изменения кода | Локальный Git-репозиторий | GitHub или GitLab API |
| Деплой | Переданный commit SHA | Интеграция с CI/CD |
| Состояние зависимостей | Health endpoints | Метрики и события мониторинга |

## Принцип первой версии

Первая рабочая версия должна пройти один сценарий полностью:

1. Получить инцидент через FastAPI.
2. Запустить расследование через Celery.
3. Проанализировать тестовые логи через LangGraph и Pydantic AI.
4. Получить структурированный отчёт.
5. Сохранить отчёт в PostgreSQL.
6. Вернуть отчёт через API.
